## 一、P0：会直接误导操作的问题（优先修）

### 1.1 结论和阶梯表在互相打脸

**实测**：上海九百 600838 的结论文案是

> ⛔ 今日不做T —— 观望（振幅 3.64%，不够 4% 门槛）

但同一张卡下方，"三个闸门 + 六档价位卡 + 七格阶梯表"照常渲染，阶梯表里清清楚楚写着 **买点 7.49 / 7.39，卖点 8.32 / 8.21 / 8.11 / 8.01 / 7.80**，红绿底色一应俱全，还有一个蓝字 `◀现价`。

更麻烦的是六张价位卡虽然加了 `.lv.off`（`opacity:.38` + 灰度），**但数字仍然清晰可读**（7.80 — 7.70 / 8.04 / 8.04 / 7.69 / 7.58 …），旁边小字标"（今日不适用）"。用户扫一眼看到的是"一堆具体价格 + 半透明的'不适用'"，而人的眼睛先抓数字。

**为什么这是 P0**：这是「决策工具」而不是「数据看板」。工具可以显示 100 个数字，但不能在说"今天别动"的同时递上一张写着七个买点卖点的挂单表。用户某一刻手一抖抄了 7.49 进去，这套系统的全部价值就归零了。

**建议改法**（按推荐度排序）：

- **方案 A（推荐）**：`mode === 'WAIT'` 时，把「六档价位卡 + 阶梯表」整块折叠成一个可点击的条：
  `⚠️ 今日不可执行 · 点击查看预案价格（仅供观察，不要挂单）`
  默认收起，展开后整块加灰度 + 顶部红字横幅。想看的还是看得到，但需要一次主动点击。
- **方案 B（改动最小）**：保留布局，把买/卖 pill 在 WAIT 时全部替换为灰色「观察」，并给阶梯表加 `filter:grayscale(1) opacity(.5)`，同时把 `◀现价` 标记保留（它仍有信息量）。
- **方案 C**：WAIT 时只保留「观察位」两行（±1 格），其余行不渲染。

### 1.2 浮点精度泄漏到可编辑输入框

**实测原始值**（探针抓取的 5 个输入框）：

```
ma5  = 22.997999999999998
ma20 = 23.964000000000006
ma5  = 7.901999999999999
ma10 = 8.318999999999999
ma20 = 8.254999999999999
```

**根因**：`computeTA()` 第 955~957 行把算出来的均线**原样**写回数据对象

```js
if (m5  !== null) s.ma5  = m5;      // ← 没有取整
```

而 `render()` 用 `value="${s[k]??''}"` 直接输出。输入框左侧标签写的是 "MA5"，里面躺着一串 17 位数字。

**为什么这是 P0**：这条和第 1.1 条是同一类风险 —— 用户会**从输入框里复制数字去挂单**。一个 22.997999999999998 的挂单价填进券商，要么被拒，要么成交在一个他自己都没算清的位置。

**修法**（两行）：

```js
// computeTA 内
if (m5  !== null) s.ma5  = +m5.toFixed(2);
if (m10 !== null) s.ma10 = +m10.toFixed(2);
if (m20 !== null) s.ma20 = +m20.toFixed(2);

// render 内，输入框统一格式化（保留小数但去掉尾随零）
const fmtIn = v => (v === '' || v == null) ? '' : String(+(+v).toFixed(3));
... value="${fmtIn(s[k])}"
```

顺带建议给所有数字输入框加 `step="0.01"`，以及 `inputmode="decimal"` 之外再加一个 `enterkeyhint="next"`。

### 1.3 `◀现价` 标记的容差是半格，会把现价"吸"到相邻档

**实测**：上海沿浦现价 **22.63**，`◀现价` 却标在 `-2.67% → 22.55` 那一行；上海九百现价 **7.81**，标记落在 `+1.33% → 7.80` 那一行（而 7.81 其实已经越过 7.80 了）。

**根因**（`render()` 内）：

```js
const isNow = Math.abs((+s.price) - p) <= c.pc * GRID / 200;   // 半格容差 ≈ ±0.15 元
```

容差是半格（0.154 元），所以现价只要落在某档附近就会被贴上标记。视觉上读者会理解成"现价就是 22.55"。

**修法**：容差收窄到 1/8 格，并且**换一种表达** —— 不要在档位行上贴"现价"，而是在表格上方加一行：

```
现价 22.63（-2.33%）│ 位于 -1格 22.86 与 -2格 22.55 之间 │ 距 -2格 支撑还有 -0.35%
```

这样"现价在哪"和"档位是多少"两件事分开说，不会混淆。

### 1.4 建议给阶梯表加一列「距现价 %」

现在只有「相对昨收 %」。「-2.67% → 22.55」到现价 22.63 还差多少，用户得自己心算。加一列 `距现价 -0.35%` 是零成本的收益。

## 二、P1：信息架构（体验的大头，也是最有价值的一块）

### 2.1 决策三要素的排序是反的

当前「四、决策引擎」里，单只股票卡片的内部顺序是：

```
表头（现价/振幅/量比/更新于）
  ↓
K线图 + 图例 + 实时数据条      ← 约 430px
  ↓
12 张技术卡（3 行）             ← 约 900px
  ↓
结论横幅 ⚠️/✅                  ← 实测在 y=2950
  ↓
三闸门 + 六档价位卡
  ↓
七格阶梯表
```

**用户每天打开这个页面，要找的是三件事**：今天能不能做、挂在哪个价、跌到哪里止损。现在这三件事被压在近 3000px 之下，而上面 1300px 全是"信息密度很高的参考数据"。

**建议顺序**（每只票的卡片内部）：

```
① 结论横幅（今天能不能做，一句话）           ← 提到最前
② 六档价位卡（买点/止盈/止损/接回/卖飞线）    ← 抄单用，最重要
③ 三闸门一行（为什么是这个结论）
④ 七格阶梯表
⑤ 11 张技术卡 + K线图  ← 默认折叠「展开图表与技术细节」
```

理由：结论和挂单价是**每天都要用**的，图表和技术卡是**判断依据、隔几天看一次就够**。默认折叠可以把卡片高度从约 1500px 压到约 400px，两只票直接省下 2000px 的滚动。

### 2.2 技术卡等高拉伸产生大片空白（实测 300px/行）

12 张卡是 `repeat(auto-fit, minmax(166px,1fr))` 的 4 列栅格。第 3 行是「RSI / 换手率 / 大单资金 / **支撑位压力位**」——最后一张卡因为要列 3 个压力位 + 3 个支撑位（每个都带标签、强度、偏离百分比），高度到了 **480~514px**，把同行的另外三张也拉到同样高度，于是它们内容只占 180px、剩下 **300px 是纯空白**（截图中那三个绿色空框）。

**修法**（推荐第 1 个，改动最小）：

1. 给长卡单独指定跨列：`.ta.t-sr{grid-column:1/-1}` —— 支撑压力位独占一整行，横排 6 个价位，既省高度又更好读。
2. 或把栅格换成 flex 多列容器（`column-count` / 手动分列），允许卡片高度各不相同。
3. 顺便把 `minmax(166px,1fr)` 提到 `minmax(210px,1fr)`，201px 的卡宽对"BOLL 22.03 / 23.96 / 25.90"这种长串数字太挤。

### 2.3 首屏给了"永远不会重读一遍"的内容

第一章「方法论内核（四条定理）」四张静态卡 + 第二章那段 500 多字的「每只股票卡片内置的图表能力」说明（含 7 个 bullet），合计占了首屏往下约 700px。

这两块是**新人第一次看的说明书**，不是每日工具。**做T是枪，不是打卡机**这句话用户看一遍就记住了，不需要每天在首屏复习。

**建议**：

- 第一章外壳改成 `<details>`，默认收起，标题写「一、方法论内核（四条定理）· 点击展开」。
- 第二章那段说明改成一个 `? 图表能力` 按钮，点了才展开（或做成图表上方的小提示）。
- 省出来的首屏还给"今天该不该动手"。

### 2.4 缺锚点导航 / 吸顶栏 / 回到顶部

9017px（手机 14244px）的页面，没有任何跳转辅助。用户想从"执行台账"回到"决策引擎"，只能滚。

**建议**：加一条吸顶迷你栏，内容 = 章节锚点（作战卡 / 账户 / 台账 / 认知）+ 当前各票现价速览 + `⟳ 刷新全部`。一栏解决"我在哪、现在什么价、怎么跳"三个问题。

### 2.5 账户总览与成本录入被分到两章，方向是反的

「三、账户总览与每日收益」在 DOM 里排在「四、决策引擎」**之前**，但「持仓成本 / 持仓股数」的输入框在第四节每只股票的卡片里。

于是首次使用的路径是：打开页面 → 看到「总资产 0 / 持仓 0 只 / 浮动盈亏 +0 / 仓位占比 —」（默认数据 `shares:0, cost:0`）→ 以为坏了 → 往下滚 2000px 才找到成本输入框 → 填完再滚回去看账户。

**建议**：

- 账户区在无持仓时不要显示一排 0，改显示一句引导 + 一个按钮：`尚未录入持仓 · [去录入成本]`，点击平滑滚动到对应股票的输入区并高亮 1.5 秒。
- 更好的做法：把「持仓成本 / 持仓股数 / 可用现金」三个框从股票卡左侧输入区**提到卡片表头下方**，因为它们属于"账户事实"而非"行情参数"，放一起更符合直觉，也顺带解决"找不找得到"的问题。

## 三、P2：交互细节与稳健性

### 3.1 每次按键都全量重建 DOM

```js
inp.addEventListener('input', e=>{
  pool[i][k] = ...;
  render(pool);        // ← 整个 #pool 的 innerHTML 重建 + 每只票 2 个 canvas 重绘 + 12 张卡重算
});
```

单只票尚可，三只以上会明显掉帧。中文输入法更麻烦：**没有 `compositionstart/compositionend` 守卫**，拼音打字过程中 `parseFloat` 会拿到 `"2"`、`"22"` 这类中间态，导致每敲一个字母页面就重算一次并可能把值写成半成品。

**建议**：

- 加组合输入守卫：`compositionstart` 置 `_composing=true`，`compositionend` 再触发一次 update。
- 把 `input` 处理改成 `requestAnimationFrame` 合并（同一帧内多次输入只算一次）。
- 中期方向：把 `.outputs` 区拆成若干可独立 patch 的片段，输入时只更新文本节点与那 12 张卡的数值，不重建 DOM，也不重绘 canvas。

### 3.2 自动刷新每 60 秒整段重渲染

`setInterval` → `refreshAll(true)` → `render(pool)`。虽然已经避开了"正在输入"的场景，但整页重绘会闪一下，并且**清掉图表上的悬停十字光标**（`_hover` 状态存在闭包/全局里，DOM 重建后位置对不上）。而且守卫只判断了 `#pool` 和 `#logTable`，**漏了 `#dbInput`** —— 正在检索框里打字时会被打断。

**建议**：`ae.closest('#dbInput')` 一起加进守卫；刷新改为"只更新数字层"，或给一个 `⏸ 暂停自动刷新` 开关（盘中盯盘用户可能更想要手动节奏）。

### 3.3 手动输入 vs 自动取数的优先级没有定义

用户手填一个价格（比如网络断了，或者想试算"如果涨到 24 我会怎么操作"），60 秒后自动刷新会把行情盖上去，手填值静默消失，也没有任何"已手动修改"的标记。

**建议**：给可编辑字段加"已手改"状态 —— 被手动改过的字段显示一个浅黄底或小圆点，自动刷新时**跳过**这些字段，并提供 `⟲ 恢复为行情值`。这在"用系统做假设推演"时非常有用。

### 3.4 两个「添加自选股」按钮同名不同义

| 位置 | 按钮文字 | 实际行为 |
|---|---|---|
| 「二、自选股与自动取数」 | `＋ 添加` | 走 `addByQuery()`，联网检索代码/名称/拼音后添加 |
| 「四、决策引擎」操作条 | `＋ 添加自选股` | 直接 `pool.push({name:'手动一行', price:10, prevClose:10, ...})` —— 插入一行价格全 10 元的占位数据 |

后者的行为相当危险：如果原来持有一只 22 元的票，插入这行"全 10 元"的占位数据后，账户区会立刻多出一个 `-54%` 的浮亏，而用户只是想"加一只票"。

**建议**：第四节这个按钮改名为 `＋ 手动新增空白行`（并把默认价格改成空而非 10），或者干脆删掉 —— 第二节那个入口已经够用。

### 3.5 工具条 chip 密度过高

单只票的图表工具条 = 9 个周期 + 5 个叠加 + 2 个副图 + 大单资金 ≈ **18 个 chip**，另有 3 个分隔线和 3 个标签。窄屏下会折成 4~5 行。

**建议**：周期收成「分时 / 日 / 周 / 月」4 个常用 + `更多 ▾` 下拉；叠加项收进一个 `叠加 ▾` 面板。手机端 pageH 14244px 里有相当一部分来自这里。

### 3.6 缺少"复制今日作战计划"（投入产出比最高的一条）

现在只有「复制体检报告（纯文本）」。但用户每天真正需要带走的是：

```
上海沿浦 605128　现价 22.63（-2.33%）
  判定：日线空头，只做倒T
  倒T卖出区：22.86 ~ 23.17
  倒T接回位：22.55 / 22.24
  卖飞线：23.20（放量突破即认卖飞，不接）
  T仓：— 股（30%），每份 — 股
```

一键复制 → 微信粘贴。**建议放在每只票的结论横幅右侧**，做成 `📋 复制本票计划`，再在账户区上方加一个 `📋 复制全部计划`。这一条几乎零风险，收益直接。

### 3.7 数据只在 localStorage，没有导出/备份

`t-system-pool` / `t-system-log` / `t-system-snap` / `t-system-red` / `t-system-checkup` 五个键全在浏览器里。清缓存、换浏览器、换电脑即全部丢失。而台账和认知体检的价值恰恰在**跨月累积**（T1 明确建议每月对比分数变化）。

**建议**：加「导出全部数据（JSON）」+「导入」两个按钮，并把导出的文件名带上日期。低成本、高价值。

### 3.8 缺键盘快捷键

## 二、P1：四个影响日常使用的问题

**1）刷新失败时，旧数据没有任何视觉标记。**
`refreshAll()` 会把失败信息汇总成第二章的一行小字（`部分未更新 → …`），但**页面上的价格照常显示**，
没有任何"这是旧数据"的标记。你的笔记本有网络不稳的历史，10:00 刷新失败时，
你看到的可能还是 9:00 的价格，而那行提示早就滚出视野了。
修法：顶部吸顶栏常显「数据时间 HH:MM:SS」，超过 3 分钟未更新则整栏转黄 + 价格区加淡色斜纹。

**2）没有价格到位提醒。**
全页 0 处 `Notification` / 0 处声音 / `document.title` 固定不变。
现价触及买点或卖点时必须你自己盯着看。
修法：`document.title` 动态显示「⚡ 上海沿浦 22.55 触及买点」，配合可选的桌面通知（首次需授权）。

**3）触控目标普遍 <30px。**
28 个可点击元素不达标：吸顶导航链接 27px、工具条按钮 25px、`dbAuto` 复选框 13px。
手机端改 `min-height:34px` + 复选框改整行可点。

**4）次要文字颜色过淡（`--mute` #94a3b8，对比度 2.56）。**
55 处引用，全是说明文字与字段标签。改 `#64748b` → 对比度 4.76，一行变量改动。

## 四、验真方式（每条都能复现）

对比度用同一段探针复算：取 `getComputedStyle(el).color` 与逐级上溯得到的首个不透明
`backgroundColor`，套 WCAG 相对亮度公式。验收标准：`ratio ≥ 4.5` 的元素占比 100%。
触控尺寸用 `getBoundingClientRect().height ≥ 30`，字号用 `font-size ≥ 11.5px` 抽样复核。

**注意**：颜色改动后必须重新截图肉眼确认一遍 —— 对比度是一个可算的数，
但"A股用户看着这红色像不像涨"是主观判断，两者都要过。

# 第三轮：卡片切换式视图（2026-09-20 21:50）

起因：用户问「做成卡片式的会不会更好，单个股票可以直接切换」。

**结论：会，但要做成「单票聚焦 + 全部总览」双模式，不能只有切换。**
纯切换的缺陷是会丢掉盘前横着对比所有票的能力；纯堆叠的缺陷是票一多就要滚很久。
两者并存，默认单票，记住了选择。

备份：`_backup_20260920_2150_pre_tabs.html`。

## 一、设计要点（4 个关键决策）

| # | 决策 | 为什么 |
|---|---|---|
| 1 | **切换用 CSS 过滤，不改渲染逻辑** | `render()` 全量渲染所有卡片，再用 `#pool[data-view=one] > .card{display:none}` 藏掉非当前的。因为 `data-i`（输入框索引）、`canvas[data-ki]`（图表索引）全部按 `pool` 下标走，**如果在渲染阶段过滤，显示下标与 pool 下标就会错位，输入框会改错股票**。代价是所有票都在 DOM 里，换零索引风险，值。 |
| 2 | **切换条只占一行，票多了横滑** | 换行会随票数把条越撑越高。实测 8 只票时折成 3 行（131px），把结论从 y=853 挤到 y=1027（掉出首屏）。改单行横滑后固定 58px。可横滑时右缘加渐隐提示「后面还有」。 |
| 3 | **切换条吸顶** | 决策区一滚就是一两千像素，标签吸在吸顶栏正下方，盘中换票不用滚回顶部。偏移量由 `renderPoolTabs()` 按吸顶栏真实高度写进 `--tb-h`（吸顶栏会随宽度换行变高，写死数字会被盖住）。窄屏不吸：手机上会吃掉太多屏幕。 |
| 4 | **标签上带策略徽标** | 不只看名字：`正T / 倒T / 只减 / 观望` 四色徽标 + 现价 + 涨跌。扫一眼就知道今天哪只能动、往哪个方向动。 |

配套：`←` `→` 切票（输入框内不抢光标）；`🔥 全部 N 只` 一键回到总览；选择记进 localStorage；打印时强制展开全部卡片（纸上要的是全套）。

# 第四轮：配色收敛与色相分离（2026-09-20 22:10）

## 二、改法：六槽语义色板，一个色相只干一件事

| 槽 | 语义 | 色相 | 用在哪 |
|---|---|---|---|
| ① 方向 | 涨/卖 **红 0°** 、跌/买 **绿 149°** | 锚点不动 | 只给价格、金额、涨跌幅数字和 K 线，不做判定 |
| ② 判定 | 止损/风险/数据陈旧 **金 40°** | `#b45309`(26°) → `#9a6700`(40°) | 止损价、只减档、陈旧警示、手工改值输入框 |
| ③ 信息 | 现价/焦点/行业标签 **蓝 221°** | 不变 | 现价标记、当前周期、行业标签 |
| ④ 我的 | 成本/做T收益/手工覆盖 **紫 262°** | 不变，但**独占** | 成本线、做T已实现、RS 曲线、概念标签 |
| ⑤ 参照 | 低风险/二级分类/叠加指标 **青 193°** | `#0f766e`(175°) → `#0e7490`(193°) | 风险C档、板块二级、叠加按钮、分时均价线 |
| ⑥ 中性 | 文字 3 档 + 底/线 3 档 | 5 档灰 → 3 档 | 让"档位"本身成为信息 |

两条设计原则写在代码注释里，后面加色时照着判断：

1. **"徽章管判定、数字管方向"** —— 同一屏里绿色可以既表示"跌"又表示"可以买"，因为徽章有色块＋边框、数字只有字色，形式不同就不会误读。
2. **暖色区一个萝卜一个坑** —— 橙黄段只留给"判定"，图表里的 MA10/MA60/均价/箱体/BOLL 中轨全部搬走。这样即使金与红只差 40°，页面上也不会三四个橙色互相打架。

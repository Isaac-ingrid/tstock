# 选股收益跟踪 + 大盘异动提醒 · 设计方案

> 版本 v1（方案稿，未实施）｜2026-10-29
> 承接：`选股引擎/`（已上线的六步法打分版）
> 目标回答两个问题：**① 选出来的票到底有没有用？② 买卖点为什么会找不准？**

---

## 一、两个需求的本质不同，别混在一张表里

| | 需求 A：收益跟踪 | 需求 B：异动提醒 |
|---|---|---|
| 时点 | **事后** | **事中** |
| 回答的问题 | 选股规则有没有超额收益 | 执行时点对不对 |
| 失败后果 | 一直用一套没用的规则 | 买在半山腰、卖在跳水前 |
| 产出 | 统计表 + 曲线 + IC | 实时提醒条 + 动作建议 |
| 数据依赖 | 每日清单 + 历史收盘价 | 分钟级指数/板块/个股 |

两者共用同一套底座：**每日落盘的选股清单**。所以 A 必须先建，B 才有"哪些标的值得盯"的输入。

## 二、总体架构（双闭环）

```
                     ┌─────────────────────────────┐
  15:10 收盘后        │  选股引擎 engine.js          │
                     │  全市场扫描 → 打分 → 清单     │
                     └──────────────┬──────────────┘
                                    ↓
                     ┌─────────────────────────────┐
                     │  ledger/                    │
                     │  picks-YYYY-MM-DD.json      │  ← 当日清单（含得分/分项）
                     │  close-YYYY-MM-DD.json      │  ← 当日收盘价快照（全市场）
                     └──────────────┬──────────────┘
                                    ↓
                     ┌─────────────────────────────┐
        闭环① 事后验证 │  returns.js 收益回算         │
                     │  T+1..T+20 × 池别 × 得分档    │
                     │  胜率 / 超额 / IC / 回撤      │
                     └──────────────┬──────────────┘
                                    ↓
                            统计页：是否可行 → 调参

  ───────────────────────────────────────────────────────

  09:30-15:00 盘中     ┌─────────────────────────────┐
                     │  monitor.js 异动监控          │
        闭环② 事中校准 │  指数4 + 板块20-30 + 个股5-10 │
                     │  z 分数 + 量能 + 共振判定     │
                     └──────────────┬──────────────┘
                                    ↓
                     ┌─────────────────────────────┐
                     │  提醒条 / 桌面通知            │
                     │  「警告：板块跳水 → 停止正T」  │
                     └─────────────────────────────┘
```

## 三、需求 A：选股收益跟踪

### 3.1 三个必须先定死的口径（不定就没法算）

| 口径 | 选项 | 建议 |
|---|---|---|
| **买入价** | ① T 日收盘价（理想）② T+1 开盘价（可实现） | **双轨都算**，对外主看 ② |
| **卖出价** | T+n 日收盘价 | 统一用收盘，不假设日内择时 |
| **成本** | 往返 0.11%（FEE=0.0011，与做T系统一致） | 只在最终卖出日扣一次，不按天累扣 |

**为什么买入价必须双轨**：引擎在收盘后跑，收盘价是买不到的。用收盘价算出来的收益会系统性偏高——尤其在今天这种尾盘拉升的日子里，第二天往往高开，实际成交价比收盘价高一截。**只报收盘价口径，等于自己骗自己。**
`sig_close`（理想口径）用来衡量"信号本身的质量"，`sig_open`（可实现口径）用来衡量"真金白银能拿到的"，两者差值就是**隔夜跳空成本**，本身也是一个有价值的指标。

### 3.2 收益矩阵（核心表）

**行**＝选股日期，**列**＝持有天数。

| 选股日 | 池别 | 只数 | T+1 | T+2 | T+3 | T+5 | T+10 | T+20 |
|---|---|---|---|---|---|---|---|---|
| 10-29 | 短线 | 25 | — | — | — | — | — | — |
| 10-28 | 短线 | 18 | 2.31% | 3.05% | … | | | |

- 短线建议最大 T+5（对应《短线选股.md》1–5 日持仓）
- 长线/稳健建议 T+5 / T+10 / T+20 / T+60
- 每个格子＝该日清单**等权平均净收益**；同时保留单票明细供下钻

### 3.3 五个统计指标（少一个都会误判）

| 指标 | 公式 | 为什么必须有 |
|---|---|---|
| 平均收益 | mean(R) | 方向 |
| **中位数** | median(R) | 抗极值。一只连板能拉高平均，但你可能只买到别的 |
| 胜率 | 正收益只数 / 总数 | 体验感 |
| **超额收益** | mean(R) − mean(R_benchmark) | **最关键**，见下 |
| **IC（秩相关）** | Spearman(得分, 收益) | 验证打分卡有没有信息量 |
| 最大回撤 | 持有期内 max(1 − P/P_max) | 敢不敢拿 |

**超额收益为什么最关键**：假设 25 只平均涨 3%，而同期中证 1000 涨 3.5%——选股是**负 alpha**，你只是吃到了小盘风格的 beta，换成随便买一篮子小盘股结果一样。**只看绝对收益永远发现不了这件事。**

**基准建议**：

| 池别 | 主基准 | 说明 |
|---|---|---|
| 短线 | 中证 1000（sh000852） | 小盘风格代理 |
| 稳健 | 沪深 300（sh000300） | 大盘风格代理 |
| 全部 | 全 A 等权（自算） | 最严格的对照：选股 vs 随机一篮子 |

### 3.4 三个对比实验（这才是"是否可行"的答案）

| 实验 | 怎么比 | 什么结论算"可行" |
|---|---|---|
| **① 得分单调性** | ≥80 分 / 70–79 / 60–69 三档的 T+3 收益 | 递增才说明打分卡有信息量；打平说明六个维度白设了 |
| **② 规则对比** | 严格六步法（0 只）vs 打分版 | 若打分版长期正超额，证明"改打分"是对的 |
| **③ 环境分层** | 发酵日 / 修复日 / 退潮日的收益 | 差距大 → 验证"环境决定成败"；差距小 → 说明我判断错了 |

**IC 的判读标准**（业界通行）：|IC| < 0.05 无信息量；0.05–0.1 弱；> 0.1 可用。样本 < 20 个交易日的 IC 没有统计意义，只作方向参考——与《认知台账》"<20 笔标注仅供参考"的口径一致。

### 3.5 存储结构

```
ledger/
  picks-2026-10-29.json     # 当日清单（代码/名称/得分/分项/VWAP统计/涨停日）
  close-2026-10-29.json     # 当日全市场收盘价+涨跌幅（东财快照，已有）
  returns.csv               # 回算结果，按 (选股日, 代码, 持有天数) 追加
  stats-weekly.json         # 周度汇总（矩阵 + IC + 超额）
```

**为什么要单独存 close 快照**：收益是"未来"才发生的。今天不存，三个月后回补要按每只票单独拉历史，成本高且容易漏。**每天存一份全市场收盘，只花 1 次全量快照的代价，是这套系统最划算的一笔投资。**

**复权陷阱**：收益必须用**前复权**价格算，但前复权在除权日会重算历史。仓库里要记录每只票的复权因子变化，遇到除权日标注"该笔收益已重算"，否则会出现"昨天赚 3%、今天变 2.7%"的诡异现象。

### 3.6 统计页面

四块内容，从上到下：

1. **累计收益曲线**：短线 / 稳健 / 基准三条线叠在一张图（红涨绿跌）；
2. **得分档 × 持有期 热力矩阵**：一眼看出"高分档在 T+3 是否更红"；
3. **逐日明细表**：最近 20 个交易日，每行可点开看当日清单与单票收益；
4. **样本量与置信提示**：不足 20 个交易日时顶部挂黄色横幅"样本不足，结论仅供参考"。

## 四、需求 B：大盘 / 板块异动提醒

### 4.1 监控对象分三层（不做全量，噪音会淹掉信号）

| 层 | 标的 | 数量 | 数据源 | 频率 |
|---|---|---|---|---|
| L1 大盘 | 上证 / 深成 / 创业板指 / 中证 1000 | 4 | 腾讯指数分时（已验证可用） | 3 秒 |
| L2 板块 | 持仓相关 + 当日涨幅前 10 + 跌幅前 10 | 20–30 | 腾讯板块分时（已验证可用） | 5 秒 |
| L3 个股 | 持仓 + 当日候选 | 5–10 | 现有做T系统 | 3 秒 |

**为什么不全盯 124 个申万二级板块**：盘中平均每分钟有 3–5 个板块发生 1% 级别波动，全量监控等于每分钟弹 5 次窗，三天后你就会关掉它。**提醒的价值取决于"少而准"，不是"全"。**

### 4.2 "突然"怎么定义——不要用固定百分比

固定阈值（比如"5 分钟涨 1%"）在平静日永远不触发、在暴跌日每秒触发。改用**波动标准化**：

```
r5   = 最近 5 分钟收益率
σ    = 当日已发生分钟收益的标准差
z    = |r5| / (σ × √5)
```

| z 值 | 含义 | 分级 |
|---|---|---|
| ≥ 2.5 | 偏离常态 2.5 个标准差 | 提示 |
| ≥ 3.5 | 明显异动 | 警告 |
| ≥ 5.0 | 极端异动 | 紧急 |

好处：自适应。平静日 0.15% 就算异动，剧烈日 1.2% 才算。**同一套阈值在两种行情下都不会失效。**

**再加三个确认条件（缺一不报）**：

| 条件 | 规则 | 作用 |
|---|---|---|
| 量能确认 | 该 5 分钟成交量 > 当日均量 × 1.8 | 过滤无量假摔/假拉 |
| 方向确认 | 与当日主趋势同向，或突破关键位 | 过滤震荡噪音 |
| 冷却期 | 同一标的 20 分钟内不重复提醒 | 防刷屏 |

### 4.3 提醒必须带动作（这是需求的核心）

| 触发 | 级别 | 建议动作 |
|---|---|---|
| 向下 z≥3.5 + 放量 | 警告 | **停止正T**；持仓检查是否触及止损位 |
| 向下 z≥5，或跌破 MA20 / 20 日箱底 | 紧急 | **只做倒T减仓**，禁止低吸 |
| 向上 z≥3.5 + 放量 | 警告 | **不追高**，挂回踩均价线的单 |
| 向上突破箱顶 + 量能放大 | 紧急 | 可跟随，但仓位减半、止损上移到突破位 |
| 板块异动但个股不动 | 提示 | 检查是否被板块落下（补涨机会 vs 风险） |

**关键原则：提醒 ≠ "告诉你涨了"。** 一条只说"XX 板块涨了 2%"的提醒，除了让你焦虑没有任何作用。每条提醒必须给出"你现在该做什么"。

### 4.4 板块共振判定——这才是"买卖点找不准"的根源

用户的原话是"否则买点或卖点会找不准"。真正的病根不是不知道涨跌，而是**分不清是个股自己在动，还是板块在带**。四种情形，操作完全相反：

| 板块 5min | 个股 5min | 判定 | 操作含义 |
|---|---|---|---|
| 强势（>1.5%） | 强于板块 1.5 倍 | **个股领涨** | 最强结构，回踩可做正T |
| 强势 | 跟涨但弱于板块 | **板块共振（跟风）** | 持续性差，只做首波，不接第二波 |
| 平淡 | 独立异动 | **个股行为** | 先查消息，无消息多为试盘 |
| **跳水** | **抗跌（跌幅<板块一半）** | **逆势抗跌** | 往往是 T 的最佳标的，但要等板块止跌 |

最后一行是这套监控真正的价值点：**板块跳水时个股抗跌，是正T最好的入场信号**——而这个信号只能通过"板块 vs 个股"的相对强度实时捕捉，靠盯个股永远看不出来。

### 4.5 提醒通道

| 通道 | 可行性 | 说明 |
|---|---|---|
| 页面横幅 + 声音 | ✅ 直接做 | 现有系统已有 `tbNotify` 基础 |
| 桌面通知（Notification API） | ✅ 直接做 | **页面必须开着**，否则不触发 |
| 微信推送 | ⚠️ 需第三方 | 企业微信连接器当前是关闭的；可行路径是 Server酱 / PushPlus，需你提供 SendKey |
| 常驻后台 + 7×24 推送 | ⚠️ 成本高一档 | 需 Node 进程常驻 + 推送服务 |

**诚实说明**：页面内提醒的实际可用性取决于"盘中页面是否开着"。如果你盘中用手机看盘，这套东西基本无效——那时应该改用微信推送。

### 4.6 已知数据限制（现在说清，免得后面返工）

| 限制 | 影响 | 应对 |
|---|---|---|
| 板块分时只有「价格 + 累计量」，**没有累计额** | 板块算不了均价线（VWAP），个股可以 | 板块只做涨跌幅异动，不判均价关系 |
| 免费源**没有历史分钟数据** | z 阈值无法用历史回测校准 | 用当日滚动分位数自适应 + 实盘人工调 2 周 |
| 无实时涨跌家数（市场总览接口是 T-1） | 市场宽度指标滞后 | 用 124 个板块的 upCount 汇总近似（已验证接口返回 "7/9" 这类字段） |
| 指数分时有累计额 | 指数可算 VWAP，可判"价在均价上方/下方" | 用作大盘多空的第一道判断 |

## 五、分阶段实施

| 阶段 | 内容 | 依赖 | 产出 |
|---|---|---|---|
| **P1** | ledger 落盘 + `returns.js` 回算 + 统计页 | 无（引擎已上线） | **"是否可行"的答案** |
| **P2** | `monitor.js` 异动监控（L1+L2+L3）+ 页面提醒条 + 桌面通知 | P1 的候选清单 | 盘中动作校准 |
| **P3** | z 阈值校准（用 P1/P2 积累的真实触发记录）+ 微信推送 | P1/P2 显示有必要 | 降噪 + 移动端提醒 |

**为什么 P1 必须先做**：异动阈值的松紧，只有拿到"哪些票在什么环境下赚了钱"的数据才能定。没有 P1，P2 的调参就是拍脑袋。而且你要回答的"是否可行"，只有 P1 能回答。

**建议节奏**：P1 现在做；跑满 20 个交易日（约一个月）后再用数据决定 P2 的阈值。

| # | 决策点 | 选项 | 我的建议 |

| 1 | 买入价口径 | 只用 T+1 开盘 / 双轨都算 | **双轨**，隔夜跳空本身就是要测的东西 |

## 七、风险与局限

1. **样本期太短会得出错误结论**。20 个交易日 × 25 只 = 500 个样本，勉强够看方向；要判断 IC 稳定性，至少 3 个月。
2. **单边行情会放大 or 抹平 alpha**。2026-10-29 这种退潮日，任何短线策略都是负收益，不能据此否定规则——必须看**超额**而非绝对收益。
3. **收益统计不含滑点**。10 万资金量下小盘股滑点约 0.1–0.3%，实际收益会比统计低一档。
4. **异动提醒在极端行情会失灵**。跌停/涨停封死时价格不动，z 值反而变小，此时"没提醒"不代表"没风险"。
5. **本方案的所有阈值均为初始经验值**，未经历史校准；标注【假设】的部分需实盘验证后再固化。

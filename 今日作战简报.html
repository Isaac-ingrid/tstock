流程一天里这套系统做四件事

为什么分两个进程：选股要扫全市场 5000+ 只，只能收盘后由 Node 批量算（浏览器扛不住，也拿不到全市场接口）； 执行台要实时刷新，只能盘中在浏览器里跑。两者用 data/latest.js 交接——不是把两份代码塞进一个文件， 而是共用一份数据契约。这样每天引擎重写数据，也不会碰到手改的执行台。

结构这个项目里有什么

index.html                  ← 本页：今日作战台（只读 data/latest.js）
做T执行台.html              ← 执行台：盘中实时行情、七格箱体、账户与台账（数据存 localStorage）
选股引擎/                     ← Node 脚本：收盘后跑，产出全部数据
  engine.js  全市场扫描 → out/<日期>.json + ledger/picks、close
  plan.js    三闸门定买卖点 → out/plan-<日期>.json
  publish.js 聚合成统一契约 → data/latest.json + data/latest.js   ★ 两个页面的交汇点
  auction.js 次日 9:26 竞价校准 → ledger/auction-<日期>.json
  returns.js 台账回算 T+1…T+20 双口径收益 → ledger/returns.csv
  steady.js  稳健底仓（周五跑）
  backtest.js / timing.js / compare.js  三个验证脚本（回溯、时段、双开关）
data/latest.json / .js       ← 契约本体 + 浏览器版（window.WB_LATEST），file:// 页面靠 .js 读取
docs/                        ← 方法论与口径（长线做T选股、短线选股、两份口径说明、可行性评估）
K线形态与盘口行为实战手册.html ← 形态与盘口信号的独立手册（不参与自动流程）
_backup/                     ← 历次改动前的整页快照，出问题直接回滚
一处刻意的不对称：引擎写 data/，执行台的账户与台账写 localStorage。 前者是"每天重算的客观数据"，后者是"你亲手记的持仓与复盘"，两类东西混在一起，一旦某天引擎跑挂就会连你的持仓一起丢。 顶栏的「导出」可以随时把后者备份成 JSON。
数据由 选股引擎/ 下的 Node 脚本生成，每个交易日 15:10 自动运行，次日 9:26 竞价校准。
